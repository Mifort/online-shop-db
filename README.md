# Online Shop Database (PostgreSQL)

Реляционная база данных интернет-магазина, развёрнутая в Docker на базе **PostgreSQL 18**. Проект спроектирован с упором на целостность данных, безопасность при параллельном доступе (concurrency safety), автоматизацию бизнес-логики через триггеры и оптимизацию частых аналитических запросов.

## 🚀 Быстрый старт

### 1. Требования
- [Docker](https://www.docker.com/) и Docker Compose.
- Клиент `psql` (или вызовы через `docker exec`).

### 2. Запуск PostgreSQL
Запустите контейнер из корневой директории:

```bash
docker compose up -d
```

Параметры подключения:
- **Хост:** `localhost`
- **Порт:** `5432`
- **База данных:** `shop`
- **Пользователь:** `shop`
- **Пароль:** `shop`

### 3. Применение схемы базы данных
Для создания таблиц, процедур, функций и триггеров примените скрипт `sql/online_shop.sql`:

```bash
docker exec -i pg18-shop psql -U shop -d shop -v ON_ERROR_STOP=1 < sql/online_shop.sql
```

> **Идемпотентность:** Скрипт `sql/online_shop.sql` выполняется в единой транзакции (`BEGIN ... COMMIT`). При повторном запуске он безопасно пересоздаёт схему с нуля, гарантируя атомарность инициализации.

### 4. Остановка контейнера
```bash
docker compose stop
```

## 💡 Архитектурные особенности и ключевые решения

1. **Историческая неизменность стоимости заказов (`order_details.price`):**
   - В позициях заказа фиксируется цена товара на момент покупки через триггер `trg_order_details_set_price`.
   - Последующие изменения цен или скидок в каталоге (`products.price`) не искажают финансовую историю оформленных ранее заказов.

2. **Защита от Race Conditions и взаимных блокировок (Deadlocks):**
   - Расчёт среднего рейтинга товара (`products.rating`) в функции `refresh_product_rating` выполняется с явной блокировкой строки товара через `SELECT ... FOR UPDATE`.
   - При переносе отзыва с одного товара на другой триггер блокирует строки обоих товаров строго в порядке возрастания их `id`, что исключает возникновение взаимных блокировок при одновременных транзакциях.

3. **Оптимизация выборки через частичные индексы (Partial Indexes):**
   - Для запроса выборки товаров с высоким рейтингом создан частичный индекс `reviews(product_id) WHERE rating > 3`. Он индексирует только оценки 4 и 5, экономя дисковое пространство и ускоряя сканирование.

4. **Строгая валидация и нормализация данных на уровне СУБД:**
   - Таблица `users` защищена ограничениями `CHECK`: проверка формата email регулярным выражением (`users_email_format`) и принудительное требование нормализованного нижнего регистра (`users_email_normalized`).
   - Хранимые процедуры выполняют нормализацию (`lower(btrim(email))`), защищая от человеческих ошибок на уровне клиентского API.

5. **Стратегия внешних ключей (Foreign Keys Integrity):**
   - `ON DELETE RESTRICT` на критических сущностях (`categories`, `products`, `users`) предотвращает случайное удаление данных, если к ним привязаны заказы или отзывы.
   - `ON DELETE CASCADE` для связки `orders` -> `order_details` гарантирует консистентную очистку состава заказа при его удалении.

## 🗄️ Схема базы данных

База данных включает 6 основных таблиц:

1. **`categories`** — категории товаров (`id`, `name UNIQUE`).
2. **`products`** — товары (`id`, `name`, `price >= 0`, `category_id`, `rating`).
3. **`users`** — пользователи (`id`, `name`, `email UNIQUE`).
4. **`orders`** — заказы клиентов (`id`, `user_id`, `order_date`).
5. **`order_details`** — состав заказов (`id`, `order_id`, `product_id`, `quantity > 0`, `price >= 0`). Составной уникальный ключ `(order_id, product_id)`.
6. **`reviews`** — отзывы клиентов (`id`, `product_id`, `user_id`, `rating CHECK (1..5)`, `comment`). Ограничение `UNIQUE (product_id, user_id)` (один отзыв от пользователя на товар).

---

## ⚡ Индексы

- `users(email)` — быстрый поиск пользователя и выборка заказов по email.
- `products(category_id)` — фильтрация товаров по категории.
- `orders(user_id, order_date)` — составной индекс для истории заказов и подсчёта покупок за период.
- `order_details(order_id, product_id)` — составной уникальный индекс (покрывает поиск позиций по `order_id`).
- `order_details(product_id)` — быстрый поиск заказов с конкретным товаром.
- `reviews(user_id)` — выборка отзывов конкретного пользователя.
- `reviews(product_id) WHERE rating > 3` — частичный индекс для быстрого поиска товаров с положительными отзывами.

## ⚙️ Логика и объекты базы данных

### Хранимые процедуры (PL/pgSQL)
Реализуют безопасные CRUD-операции с валидацией входных параметров и человекочитаемыми сообщениями об ошибках:
- **Товары:** `add_product(name, price, category_id, INOUT id)`, `update_product(...)`, `delete_product(id)`.
- **Пользователи:** `add_user(name, email, INOUT id)`, `update_user(...)`, `delete_user(id)`.
- **Заказы:** `add_order(user_id, order_date, INOUT id)`, `update_order(...)`, `delete_order(id)`.
- **Отзывы:** `add_review(product_id, user_id, rating, comment, INOUT id)`, `update_review(...)`, `delete_review(id)`.

### Триггеры
- **`trg_order_details_set_price`** (`BEFORE INSERT OR UPDATE OF product_id ON order_details`) — автоматически подтягивает цену из каталога товаров в момент добавления/изменения позиции.
- **`trg_reviews_refresh_product_rating`** (`AFTER INSERT OR UPDATE OR DELETE ON reviews`) — автоматически пересчитывает средний рейтинг товара `products.rating` (с округлением до сотых) при любых изменениях в отзывах.

### Аналитические представления (Views)
- **`v_orders_with_user_and_product`** — детальная сводка по каждой позиции заказа (номер заказа, дата, клиент, товар, количество, цена и сумма позиции).
- **`v_user_order_stats`** — агрегированная статистика по покупателям: общее число заказов и суммарная стоимость покупок.

### Функции
- **`get_orders_by_email(email)`** — возвращает все заказы пользователя по его email с подсчётом позиций и итоговой суммы заказа.
- **`get_products_with_high_rating(category_id)`** — возвращает товары выбранной категории, имеющие отзывы с оценкой выше 3.
- **`user_orders_total(user_id, date_from, date_to)`** — вычисляет сумму заказов пользователя за полуоткрытый интервал `[date_from, date_to)`.
- **`product_avg_rating(product_id)`** — возвращает точный средний рейтинг конкретного товара.
